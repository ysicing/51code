# 使用说明

[返回首页](../README.md)

## 错误提示

操作失败时，直接弹出统一的错误窗口，无需先点击「查看详情」。已识别的分支占用、未合并提交、合并冲突、身份验证、网络及权限错误会提供相应说明，无法识别的错误仍可查看完整原始信息。

详情中的原始日志支持选择、滚动和「复制详情」。点击「关闭」、标题栏关闭入口、按 `Esc` 或点击窗口外均可关闭，并清除同一条底部提示；表单操作失败时，关闭错误窗口会返回原表单，保留草稿和校验信息。输入校验继续就近显示，后台自动刷新等提示仍通过底部提示条查看。

## 内存诊断

在「应用设置 → 通用」底部的「诊断」分组点击「导出…」，选择保存目录。应用会在其中创建独立的 `51code-memory-日期时间-随机后缀` 文件夹，包含 `heap.pprof`、`allocs.pprof`、`goroutine.pprof` 和 `memstats.json`。导出完成后可查看保存路径并在文件管理器中打开。

诊断仅在点击时采集，在后台执行；采集前会触发一次 Go 垃圾回收，可能产生短暂停顿。文件包含 Go 内存采样、调用栈及运行时内存统计，不代表整个进程的原生界面或 GPU 内存占用。文件仅保存到所选目录，不自动上传。可使用 `go tool pprof heap.pprof` 等命令分析；共享前请留意调用栈中的本地构建路径。

## 仓库与快捷键

仓库列表与仓库工作区使用独立窗口。点击仓库打开对应窗口，列表保留搜索和分组；再次打开同一路径会激活已有窗口，从子目录或符号链接打开也会定位到同一窗口。不同 Worktree 各自开窗，可并排操作。

每个仓库窗口独立保留文件选择、历史、搜索、Diff 与后台任务，提交草稿按仓库保存。侧栏的“返回仓库列表”或“文件 → 本地仓库”只显示并激活列表窗口，不关闭当前仓库；关闭列表后仍可从该入口重新打开。应用设置由所有窗口共享，同时只打开一份，避免未保存的设置草稿互相覆盖。

关闭一个窗口不会关闭其他窗口。写操作、未保存的冲突编辑、身份修改和 API 密钥继续受关闭保护；退出应用时先检查所有窗口，任一窗口阻止退出时保留全部窗口。各仓库的窗口位置与大小分别记忆。

仓库管理仅收录本机已有仓库，不提供远端仓库浏览或克隆入口；已打开仓库仍支持 fetch/pull/push。旧版本的最近仓库记录自动保留，仓库组及本地列表持久化存储。移除列表记录不会删除磁盘文件。列表中的分支和变更数来自最近一次读取，可在本地仓库界面刷新；无法读取的仓库保留在列表中并标明状态。

仓库列表显示主要编程语言及对应色点，悬停可查看前三种语言的源码字节占比；紧凑窗口隐藏语言列。统计基于当前 `HEAD` 的已提交内容，测试代码计入，第三方依赖、生成代码、文档、配置、二进制、符号链接及子模块不计入；未提交内容不影响结果，无提交或未识别时隐藏标识。语言分析在后台串行执行，首次显示后缓存。返回列表、切回窗口及后台任务结束触发的自动检查至少间隔 30 秒，已有同一批仓库的检查正在运行时合并请求；手动刷新绕过节流，仓库增删立即更新检查范围。文件树未变时复用结果，读取失败保留旧结果。从列表移除的仓库及历史遗留缓存，在下一轮后台检查中清理。

先展示所有仓库的缓存，再根据系统资源安排分析。macOS、Windows 和 Linux 使用统一的 gopsutil 采样与调度策略：CPU 在 500 毫秒区间内的利用率达到 85%，或可用物理内存同时不高于总量的 5% 和 512 MiB 时延后分析，每 5 秒复查；正常采样结果复用 5 秒。内存统一采用 gopsutil 的 Available 指标，以比例和绝对余量共同判断，避免平台回收口径差异导致过度等待。单次资源等待最多 30 秒，超时或读取失败保留已有标识，等待下次刷新重试。资源等待不占用前台忙碌状态及单仓库分析超时，手动刷新、仓库增删或关闭窗口可取消等待。

每仓库最多读取 20,000 个候选文件、32 MiB 对象内容，保留的候选元数据最多 4 MiB，单文件上限 1 MiB，识别样本最多 64 KiB；触及文件或字节上限时仅展示已识别语言，不显示百分比，超时不替换旧结果。暂不支持 `.gitattributes` 中的 Linguist 覆盖规则。

仓库列表或当前分组为空时，中央显示“添加仓库”，下方提供“输入路径”和“扫描文件夹”，隐藏搜索框及顶部重复入口。添加后显示列表并恢复顶部入口与搜索框；从空分组添加时默认归入当前分组。搜索无结果时保留搜索框及“清除搜索”，不切换成首次添加界面。

扫描支持普通仓库和 Git 链接工作树，不跟随子目录符号链接，跳过隐藏目录、`node_modules` 和 `vendor`，最多扫描 12 层、20,000 个目录或 2,000 个仓库，并支持取消。达到上限或遇到无法读取的目录时会提示；扫描超时或中途出错但已找到仓库时，仍列出已找到的仓库并提示扫描未完成。扫描本身只读取，只有勾选并添加后才保存到本地列表；加入列表不会自动打开仓库。

从其他窗口切回时，仅在后台检查当前仓库，不进入全局忙碌状态。未变化的列表和预览保持原样；外部文件修改更新相关状态及正在查看的内容，分支、标签等引用变化才重读已加载的历史范围，保留选择与滚动位置。仓库列表仅自动检查语言信息，分支和变更数仍可用工具栏或 `⌘R` 手动刷新。弹窗、读取、写操作或未保存的冲突编辑期间跳过自动检查。

| 快捷键 | 操作 |
| --- | --- |
| ⌘O | 添加仓库 |
| ⌘⇧O | 扫描文件夹 |
| ⌘⇧L | 本地仓库 |
| ⌘R | 刷新 |
| ⌘Enter | 提交 |

Windows 和 Ubuntu 使用 `Ctrl` 代替 `⌘`、`Alt` 代替 `⌥`，设置页显示对应平台的快捷键。macOS 关闭最后一个窗口后仍可从 Dock 再次打开；Windows 和 Ubuntu 关闭最后一个窗口后退出，写操作及未保存内容继续受关闭保护。

界面使用 MyGo Native UI。Diff 默认根据差异面板的可用宽度自动选择统一／并排布局，也可在布局菜单中手动选择；手动选择和旧版本的布局偏好会保留。支持行内变化和语法高亮、长行换行与两侧同步垂直滚动；侧栏和文件面板分隔线可拖动调整。布局、面板尺寸、文件排序和各仓库的提交说明会在正常关闭时保存，重新打开后恢复。二进制、纯重命名、权限变更及截断差异使用原始文本预览。

单文件右上角的“差异／全文”切换在原面板中只读查看完整内容，支持选择、复制和文件内查找（点击“查找”或聚焦正文后按 `⌘F`）。未暂存文件比较暂存区与工作区，已暂存文件比较 HEAD 与暂存区，历史文件比较第一父提交与该提交；全文的版本菜单沿用这两端，删除文件默认展示删除前的版本。切换差异、全文及版本会保留各自的阅读和查找状态，切换文件或读取到变化后的内容时更新。

完整文本每侧最大 1 MiB，二进制、符号链接、子模块及特殊文件不提供全文正文，也不会将截断内容当成完整文件。可读取完整两端时，Diff 可以展开补丁之外的未修改内容，并沿用 Git 原始区块；外部修改造成全文与补丁不一致时保留 Git 区块并提示刷新，刷新前暂停区块与逐行操作。整份贮藏差异不提供单文件全文切换。

文件列表分为上方的“已暂存文件”和下方的“未暂存文件”，各自独立滚动，空分区自动收紧。右键文件或目录可复制相对路径或完整路径。历史、搜索和比较中的文件列表使用相同入口，只读仓库和已删除文件同样支持复制。搜索框下方分别提供状态筛选、排序和视图菜单：

- 默认显示全部变更，可筛选冲突、未跟踪或已跟踪变更，并与路径搜索组合使用。筛选后各分区显示匹配数与总数，批量暂存和取消暂存仅作用于匹配文件；隐藏的勾选项保留选择，但不参与当前批量操作。切换仓库会清空临时筛选。
- 支持按路径、文件名或文件状态排序，以及倒序。同名或同状态的文件按完整路径排序；状态按所在暂存分区判断。排序方式和视图偏好在正常关闭后保留，旧版本的文件名排序偏好继续生效。
- 平面列表连续显示仓库相对路径，长路径可横向滚动查看；目录树按文件夹分层，目录优先，文件在所属目录内排序，支持折叠和方向键导航。悬停文件可查看完整路径，切换视图保留当前文件、Diff 和勾选状态。折叠目录只影响展示，不改变批量操作范围。

窗口顶部左侧显示仓库名称、当前分支与领先／落后数量，右侧集中放置获取、拉取、推送、分支、合并和仓库设置；最右侧齿轮打开应用设置。文件筛选与 Diff 操作保留在各自内容区域。

顶部工具栏“更多”菜单提供“贮藏更改…”和“在终端中打开”入口，后者使用设置中选择的终端打开当前仓库目录。侧栏支持方向键导航，窄窗口中放不下的工具栏操作会收进末尾的溢出菜单。

## 仓库洞察

“洞察”默认开启，可在“设置 → 通用 → 侧栏”关闭。进入当前仓库的洞察页查看提交、贡献者、活跃天数和变更文件数，以及提交活跃度、文本变更趋势、前十位贡献者与文件热点。默认最近 30 个自然日，可切换 7／30／90 天和本地分支；选择分支只改变统计范围，不检出分支。

统计仅覆盖所选分支可达的本地提交，按本地时区的提交者日期分桶，包含今天，排除合并提交；贡献者使用工作树 `.mailmap` 合并作者邮箱。文件热点按涉及提交次数排名，重命名计入新路径，二进制变更计入文件数但不计文本行数；空提交计入提交、作者与活跃天数。浅克隆会提示本地历史不完整，不会自动联网补齐。

进入洞察页才在后台读取，工具栏的获取、拉取、推送等操作照常可用。切回窗口时先刷新仓库状态，引用变化立即重读洞察，否则至少间隔 60 秒检查；工具栏刷新、`⌘R` 及其他后台任务结束后也会重新检查，后台忙碌时进入洞察页会在任务结束后读取，读取失败时可点击“重试”跳过结果缓存。切页、切换仓库、关闭功能或窗口会取消读取。按提交 SHA、作者映射、浅克隆边界、时区和日期范围缓存聚合结果，缓存最多复用 15 分钟，每个仓库只保留一份，已移出仓库列表的缓存在下次写入时清理，Dev 与正式版分别存储。旧版 Git 不支持 `--since-as-filter` 时，会先完整遍历本地可达提交，再按提交者时间筛选并统计范围内的变更，避免因提交时间倒置漏计。单次扫描最多 20 秒、20,000 条提交、32 MiB 输出，超过预算时提示缩短范围，不以部分结果替换完整统计；刷新失败时保留同范围的原有结果。

macOS 聚合缓存位于 `~/Library/Caches/51code/repository-insights/<配置目录哈希>/<仓库路径哈希>.json`，每个仓库只保留最近一次统计，不写入 Git 仓库；开关保存在各版本自己的应用偏好中。

## AI 提交说明

暂存需要提交的文件后，点击提交说明旁的“AI 生成”。默认使用本机 Magpie，优先从 `MAGPIE_ADDR` 或 `~/.config/magpie/gateway.json` 发现地址。应用设置的 AI 页分为“连接与模型”和“生成偏好”，适用于所有仓库。点击“连接”加载模型；默认优先选择可用的 `group/codex`，否则选择模型列表中的首项。连接失败可重试，没有模型时需先在 Magpie 中配置。原有手动本机地址仍使用 Magpie 协议；其凭证继续从启动环境的 `MAGPIE_API_KEY` 读取。

连接方式选择“自定义服务”后，可使用 OpenAI Responses、OpenAI Chat Completions 或 Claude Messages 协议。填写服务的 Base URL（例如 `https://api.openai.com/v1` 或 `https://api.anthropic.com/v1`），输入 API 密钥后点击“保存密钥”，再连接并选择模型；服务不提供模型列表时，可直接填写模型 ID。远程服务必须使用 HTTPS，本机服务允许 HTTP；免密的本机服务可留空密钥。

API 密钥保存在系统凭证存储中：macOS 钥匙串、Windows Credential Manager 或 Ubuntu Secret Service，按协议与服务地址分别管理，不写入普通设置文件。“清除密钥”只删除当前协议和地址对应的记录；输入新密钥后点击“取消”保留原有记录。凭证服务不可用或保存失败时保留输入草稿，不降级为明文保存。更换协议或地址不会将原密钥发送给新服务；切回“自动发现本机 Magpie”继续使用原有自动连接方式。

尚未同意 AI 发送且未选择模型时，点击“AI 生成”会先打开应用设置的 AI 页。测试连接并选择模型后，关闭设置，再次点击“AI 生成”；配置过程不会发送暂存差异，也不会自动开始生成。已使用过 AI 的用户仍可沿用自动选择模型。

生成只发送全部已暂存文件的路径和文本差异，不受文件筛选或勾选影响，不读取未暂存内容。首次生成前会提示数据发送范围；Magpie 连接的模型可能在云端运行。自定义服务会显示实际发送地址，更换协议或地址后需要重新确认。点击“开始生成”并成功保存后，授权会全局记住，跨仓库和重启不再重复提示；取消或保存失败则下次仍需确认。二进制文件只提供变更摘要；超过 96 KiB 的差异会提示拆分提交或手动填写，避免静默截断。

默认生成中文 Conventional Commit，例如 `feat(ai): 添加提交说明生成`。空草稿直接填入结果，已有草稿先显示建议，点击“采用建议”后替换；“撤销生成”恢复采用前的草稿，后续手动编辑受到保护。生成期间可取消，也能继续浏览差异或手动提交；暂存区变化、切换仓库或关闭窗口会使旧结果失效。AI 不会自动暂存、提交或推送。

生成按钮旁的菜单提供“AI 设置…”入口；连接或模型异常时也可直接“前往设置”。暂存差异超过 96 KiB 时，仅暂停 AI 生成，点击“手动填写”即可继续编写并提交。暂存内容未变化时不重复生成；调整暂存内容后恢复入口，在其他工具中调整后可切回窗口或手动刷新。

应用设置可修改默认语言与格式；仓库设置的 AI 页可单独覆盖这两项，默认跟随应用。这些偏好仅保存在 51Code 的本地设置中，不修改 Git 配置。

## Git 来源

“设置 → Git → Git 来源”可选择系统 Git 或自定义可执行文件，并查看实际路径与版本。Windows 安装包默认使用内置 Git，包含 SSH、凭证助手和 Git LFS；macOS 与 Linux 默认使用系统 Git。切换前会验证程序，保存失败保留原选择，不修改系统 PATH。

未找到 Git 时，在同一页面选择可用的 Git，或安装后点击“重新检测”。有未保存的提交身份修改时，先保存或放弃草稿再切换来源。内置 Git 随应用更新；开发模式没有随包资源时可选择系统 Git。

## Git LFS 与大文件检查

“设置 → Git”分别提供“LFS 集成”和“大文件检查”，默认开启。仓库设置的“Git / LFS”页可独立选择跟随全局、开启或关闭；恢复继承后会继续跟随全局修改。关闭 LFS 集成只隐藏客户端管理操作，不停用仓库已有的过滤器和 hooks。

大文件阈值默认 **50 MiB**，支持全局配置和仓库独立覆盖，必须为正整数；关闭检查不会清除已配置的阈值。二进制识别遵循 Git 的 `diff` 属性与驱动配置，未指定时读取有限内容样本，不因小图片或小二进制弹窗。

单文件、勾选文件、全部文件及双击暂存会先汇总检查达到阈值的文件。可以取消、普通暂存，或勾选文件后“使用 LFS 并暂存…”。LFS 转换只暂存新增的跟踪规则，保留 `.gitattributes` 中其他未暂存修改；已部分暂存的文件需要先自行处理，避免转换时将未暂存内容一起加入。已正确使用 LFS 的文件不重复提示转换。

转换失败时会恢复未被外部修改的属性草稿；原属性文件保留在 Git 索引目录下的 `.51code-lfs-attributes-*` 恢复目录。若同时发生外部编辑，保留用户内容并提示检查，不强行覆盖。

提交前还会检查实际暂存内容，覆盖终端等外部工具的暂存。当前会话中已确认且内容未变的文件不重复提示；内容变化会重新检查。检查期间索引变化时拒绝按旧结果提交，并保留提交说明。

“设置 → Git → Git LFS”可选择系统或自定义 `git-lfs`，查看版本和路径并重新检测；Windows 可使用随安装包提供的版本。未检测到工具时，可点击“安装 Git LFS…”查看安装指引、复制适用的包管理器命令，或打开官网安装说明；安装后返回设置重新检测，也可直接选择 `git-lfs` 路径。不会自动下载或安装工具。仓库设置提供本地初始化、跟踪文件状态和缺失内容下载；初始化不修改全局 Git 配置，不覆盖自定义 hook。继承全局或系统的共享 hooks 目录且缺少 LFS hooks 时，需先手动整合，不会自动写入共享目录。文件差异工具栏的 LFS 菜单支持按具体文件跟踪和取消跟踪，规则修改保留为未暂存状态。现有历史不会自动迁移。

“设置 → Git → 操作与显示”中的“换行”默认开启，对所有仓库窗口的 Diff 和全文预览生效。修改后即时保存并同步到其他窗口，重启后保留选择。

## 暂存与丢弃

“设置 → Git”中的“双击文件暂存或取消暂存”默认开启，可手动关闭。开启时，在“文件变更”或历史的“未提交更改”中双击文件行，即可暂存该文件或取消其暂存；单击仍只查看差异，复选框仍只选择文件。冲突文件不支持双击暂存，已保存的关闭设置会继续保留。

已暂存和未暂存文件分区之间的分隔线可上下拖动，聚焦后也可用方向键调整；手动调整的比例会保留到下次打开应用。两个文件列表分别滚动，首次使用时仍会按文件数量收紧较短的分区。

区块操作只支持完整预览的普通已跟踪文本修改；新增、删除、重命名、二进制、模式变更和截断预览使用整文件操作。支持跨区块勾选，逐行替换的删除行和新增行可独立选择；若选择会拼接无末尾换行的内容，会要求同时选择对应增删行。

区块应用只修改索引，保留工作区；Git 在索引锁内严格核对目标文件的旧 blob，拒绝把过期区块偏移应用到其他位置。HEAD、其他文件及工作区仍可能在版本核对后被外部修改，版本核对不是跨进程事务。

丢弃仅影响工作区，恢复为暂存区版本；支持不超过 4 MiB 的普通文件，包括恢复删除、二进制文件和删除未跟踪文件。冲突、符号链接、目录、子模块和 intent-to-add 文件需用对应工具处理。

操作前将恢复副本保存在应用数据目录的 `discard-backups` 中，不自动清理，可从工具栏“更多”菜单中的“打开恢复副本文件夹”打开：

- `metadata.json` 记录仓库、路径、时间和原权限；原本已删除的文件以 `present: false` 记录。
- `content` 保存原始字节，恢复时将其复制回原路径，并按元数据恢复权限。

副本写入失败或确认后文件、索引、HEAD 变化会中止操作；执行前再次核对，但不与外部编辑器形成跨进程事务。

## 历史、分支与远程

“设置 → Git → 历史日期”可在作者日期与提交日期之间切换，默认沿用作者日期。历史、搜索列表及提交详情同步显示所选日期；这只改变日期展示，不改变提交拓扑顺序或搜索按作者日期筛选的规则。这两项应用偏好即时生效并保存在本地，不修改 Git 配置；下方全局提交身份仍需点击“保存”。

提交详情、搜索结果和版本比较中的“已修改的文件”支持按路径、文件名或状态排序及倒序，也可切换平面列表／目录树。显示偏好与“文件变更”页共用；切换排序或视图保留所选文件和 Diff，折叠目录不清除选择，悬停可查看完整路径。

侧栏“版本比较”支持输入完整或短提交 ID、分支、标签及 `HEAD~1` 等提交表达式，输入框会补全本地／远程分支及标签的完整引用。选择“两端快照”查看基准与目标提交的直接差异；选择“共同祖先”查看两者共同祖先到目标提交的改动，适合审阅分支自身的变化。没有共同祖先或存在多个共同祖先时会提示改用快照比较。

点击“⇄”交换方向并重新比较。文件列表、Diff、全文与查找沿用现有阅读组件，比较结果不提供暂存或丢弃操作。结果固定为本次解析出的提交，并显示实际比较起点和目标；引用移动或刷新仓库后保留已加载结果，再次点击“比较”才重新解析引用。读取可取消，失败保留此前结果与输入。

提交记录和本地分支的右键菜单支持从该对象新建分支或本地标签；标签右键支持从标签对应的提交新建分支，包括附注标签。表单显示固定的创建起点，输入名称后检查本地同类名称及路径冲突，创建前再次校验，不覆盖已有引用。右键创建分支默认不切换，勾选“创建后切换到新分支”后才切换；顶部“分支”入口保留默认创建并切换的习惯。若分支已创建但切换失败，表单保留结果并提供“重试切换”，不会重复创建。创建操作不会自动推送。

仓库侧栏的“工作区”分组依次放置文件变更、提交历史、搜索、版本比较、贮藏和工作树入口，下方排列分支、标签和远端，返回仓库入口固定在底部。分支、标签和远端分类均可折叠；标签分类和各远端默认收起，避免大量引用挤占常用入口。当前分支使用圆点和加粗名称标记，蓝色行表示当前选中的引用或目录。

本地分支、远程分支和标签按 `/` 分层显示，例如 `a/b/c` 显示为 `a → b → c`，目录带文件夹图标，可点击名称或箭头折叠、展开。路径目录默认展开，在本次应用会话中，刷新、折叠父分类或目录、切换仓库后保留折叠状态；不同仓库、引用类型和远端的状态互不影响。树支持方向键导航、左右键折叠展开和回车选择，悬停可查看完整引用。

默认分支及其所在目录优先排列，其他引用保留原有排序。本地默认分支优先采用 `origin/HEAD`，其次采用各远程 HEAD 一致指向的分支；缺少明确结果时优先显示本地 `main`，再选 `master`。各远程内部按自身 HEAD 置顶默认分支，不额外联网查询。

远程分支先按远端分组，再按分支路径分层。点击具体分支打开检出窗口，检出、切换、重命名和删除操作始终使用完整引用。`HEAD` 是远端默认分支引用，仅作展示。带 `/` 的远端名称仍作为一个完整远端显示。

历史顶部可选择“所有分支／当前分支”和“显示远程分支／隐藏远程分支”，默认显示所有分支及远程分支。“当前分支”只显示从当前 HEAD 可达的提交，包含已合并历史，游离 HEAD 时仍可使用。隐藏远程分支会排除仅由远程引用可达的提交，并隐藏远程引用标签；本地分支、标签或当前 HEAD 仍可达的提交保留，不影响侧栏远端树。筛选在本次会话中保留，滚动续载及刷新沿用该范围；切换筛选重新从首屏加载，取消或失败保留原结果和范围。

历史与搜索列表中，同一提交关联的分支和标签逐个显示完整名称，保持紧凑单行；窗口较窄时可横向滚动表格查看。

工作区侧栏的“搜索”独立于“提交历史”，首次进入不自动查询，按回车或点击搜索执行。支持全部内容、提交信息、提交 ID（完整或短 SHA）、分支、文件变更和用户：全部内容匹配提交正文、作者、邮箱与 ID；分支按名称匹配本地及远程分支，返回这些分支可达的提交；文件变更匹配新增或删除行的内容；用户匹配作者或邮箱。搜索按字面值、不区分大小写，可叠加仓库相对文件路径与日期范围，日期按本地时区的作者日期计算，包含起止当天。路径保留首尾空格，不追踪重命名前的旧路径。

搜索与历史分别保留条件、结果、选择和列表滚动位置；“文件历史”会进入搜索并带入路径。“在提交历史中查看”定位搜索结果，若历史筛选排除了该提交，则切换为全部历史。修改条件后需要重新执行；滚动续载及刷新沿用上次执行的条件。首次读取 100 条，向下滚动接近已加载内容的底部时自动续载最多 500 条，不再显示“加载更多”按钮。续载保留当前提交、Diff 和阅读位置；到达末尾后停止，失败或取消后可点击“重试”继续。搜索最长 30 秒，单条提交记录最大 4 MiB；超时或取消保留此前结果及输入。提交差异中，首提交比较空树，合并提交比较第一父提交。

本地有修改时，最新历史顶部显示“未提交更改”及文件数量，包含已暂存、未暂存和未跟踪文件。点击后使用与“文件变更”页一致的分组列表、文件勾选及批量暂存／取消暂存操作，沿用相同的排序和列表／目录树偏好；历史页始终显示完整工作区，不继承文件变更页的临时筛选。勾选只选择文件，执行“暂存所选文件”或“取消暂存所选文件”才修改暂存区，也可通过差异工具栏操作单个文件、区块与所选行。操作后保持历史页和所选文件，文件移到另一分组时跟随选择。提交与冲突编辑仍通过“前往文件变更”处理，已提交记录保持只读。空心节点只连接当前 HEAD；当前 HEAD 不在列表中时不画连线。搜索页和较早历史页不显示该行。刷新保留正在查看的提交或工作区文件；工作区清空后，该行消失，若正在查看它则转为当前 HEAD 的详情。

单击标签会在历史中定位对应提交并展示文件差异，支持轻量标签和附注标签，不改变当前分支。目标超出已加载历史时读取目标所在页，可继续加载更早记录或返回最新提交；目标被当前筛选排除时保留筛选与提交详情，点击“在全部历史中查看”后才清除筛选并定位。标签右键菜单提供复制标签名、查看标签提交、从此标签新建分支和删除标签。

新建标签只创建本地轻量标签，创建目标为选中提交或当前 HEAD。普通分支删除遵循 Git 的合并检查：有可解析的上游时检查上游，否则检查 HEAD；强制删除另行确认。删除被链接工作树使用的分支时，会先检查工作树与分支状态，再确认「移除工作树并删除分支」，展示将删除的目录；当前工作树和主工作树不允许通过此入口移除。强制删除只放宽分支合并检查，不跳过工作树的文件保护。检出远程分支时创建本地跟踪分支，已有唯一跟踪分支时直接切换。

远程操作使用现有 Git/SSH 凭证，不会自动填写或交互式请求密码。Pull 只允许快进，不受 `pull.rebase` 等仓库配置影响，出现分叉时可先获取，再合并对应远程分支；拉取或切换分支会覆盖被忽略的本地文件时拒绝执行。获取、拉取、推送和克隆最长 2 小时，连接约 60 秒无响应或传输过慢时提前中断。未配置 `fetch.writeCommitGraph` 时，获取和拉取会顺带写入 commit-graph 缓存，加快大仓库历史读取。只有一个远程且已有上游时直接推送；多个远程时先选择目标远程及分支，默认选中当前上游，向其他远程推送不会改变已有上游。无上游时先发布分支，成功后自动设置上游。仅推送明确选定的分支，不强推或附带标签。

工具栏“合并”将选定的本地或远程分支合入当前分支。

也可右键非当前本地分支或远程分支，选择“将〈来源分支〉合并到〈当前分支〉…”，打开同一窗口并预选来源。右键和打开窗口不会切换分支，确认后才执行合并；远程来源使用本地最近获取的远程跟踪引用，不会自动获取或推送。当前分支及远端 `HEAD` 不提供此入口。

合并窗口提供四种方式：

- **自动（允许快进）**：可以快进时直接更新分支，分叉时创建合并提交。
- **始终创建合并提交**：使用 `--no-ff`，即使可以快进也保留合并节点；已经合入的内容不会重复提交。
- **仅允许快进**：只更新分支指针，存在分叉时拒绝合并，不修改当前分支。
- **压缩合并（Squash）**：把变更合成一次普通提交，不记录合并父关系，也不删除来源分支的提交。默认只暂存结果，勾选“合并后立即提交”后自动创建普通提交。

自动和始终创建合并提交默认勾选“合并后立即提交”，取消后保留待提交结果；但自动模式的快进仍会更新分支，若需确保检查后再提交，应选择“始终创建合并提交”。仅允许快进没有新提交，提交开关不可用；此次调用不继承分支的自定义合并策略，避免 `ours` 等策略绕过快进限制，不修改仓库配置。合并前要求工作区干净且没有进行中的 Git 操作，并检查可能被覆盖的忽略文件；冲突或提交钩子失败保留结果，修复后可手动提交或继续对应操作。

弹窗中的提交图是说明各方式的示例，不是当前仓库的结果预览。切换方式时播放一次，可点击“重播演示”；遵循系统“减少动态效果”设置，启用时直接显示静态结果。

远程设置只编辑单个获取地址，保留现有独立推送地址及其他配置；多地址配置需使用命令行修改。发布窗口展示 Git 地址重写后的实际推送地址，拒绝镜像远程和多个推送目标。发布前核对当前分支、提交及远程配置，编辑或移除远程前核对配置；外部变化会要求重新确认，这些核对不构成跨进程事务。分支发布使用明确的本地引用，远程已有不同历史时交由 Git 拒绝非快进推送。

## 贮藏与冲突

单击贮藏记录可查看 Diff。右键点击记录可选择“应用…”、“应用并移除…”或“删除…”；键盘聚焦该记录后也可以按 `Shift+F10` 打开菜单。创建贮藏时可选择包含未跟踪文件。应用贮藏发生冲突时保留贮藏记录，解决后由用户决定是否删除。

冲突编辑支持最大 1 MiB 的 UTF-8 文本，可预览基础、当前与传入版本，编辑合并结果并暂存。二进制、大文件及符号链接可以选择完整版本或删除。子模块冲突需要外部 Git 工具处理。

冲突保存会核对读取时的文件与索引版本，防止覆盖已经发生的外部编辑；普通暂存不会直接将冲突标记为解决。应用可识别 merge/rebase/cherry-pick/revert，提供继续、中止或跳过操作，但尚不支持发起交互式 rebase。

Git 操作仍会使用仓库配置的 hooks 和提交签名，应用内继续操作不会打开终端编辑器。打开仓库应与直接在该仓库运行 Git 一样，信任其配置与 hooks。

## 工作树（Worktree）

“工作区”分组中的“工作树”显示同一 Git 仓库的主工作树及链接工作树，包括分支、提交、目录，以及锁定、失效、未提交内容和忽略文件状态。选择后可打开对应工作目录；仓库的分支、暂存区和冲突状态始终来自实际打开的工作目录。切换仓库不会复用其他仓库的工作树列表。

“新建工作树…”可从指定提交创建新本地分支，或使用未被其他工作树占用的现有本地分支。目标目录不能覆盖已有内容，也不能位于另一个工作树内部；不会强制检出或重置已有分支。

选择另一个工作树，在“更多”菜单中选择“合并到当前工作树…”，确认来源与目标提交后合并。合并前要求两端无未提交内容且没有进行中的 Git 操作，目标需位于本地分支；冲突会保留合并状态，通过原有文件变更与继续／中止操作处理。

“移除工作树…”移除干净的链接工作目录，保留本地分支及其提交，不要求已合并到当前目标 HEAD。分离 HEAD 的工作树会展示提交 ID，并提示先为需要保留的提交创建分支。主工作树、当前工作树、锁定或失效目录不能移除；未跟踪且未被忽略的文件、未提交内容和进行中的 Git 操作都会阻止移除。忽略文件（如构建产物和依赖目录）不阻止移除，确认后会随整个工作目录一起删除，确认框会明确提示。对其他链接工作树选择移除时会先预检，条件不满足时显示具体原因，不提供执行按钮。合并、移除及联动删除前会再次核对目录归属、提交及状态，变化后需要重新确认；不会强制移除或自动清理其他工作树。联动操作若在目录移除后未能完成分支删除，会报告部分完成状态和确认时的提交，停止继续操作；刷新后可重新处理剩余分支。

## 应用与仓库设置

“通用 → 侧栏”可分别显示或隐藏搜索、版本比较、贮藏和工作树入口，默认全部显示。四项独立保存，对所有仓库生效；文件变更和提交历史始终保留。关闭当前页面的入口会返回文件变更，菜单、快捷键及其他操作入口仍可使用，已有贮藏记录和工作树目录不会被删除。

点击窗口右上角齿轮，或按 `⌘,` 打开应用设置，通过顶部标签切换“通用 / Git / 快捷键 / 更新 / AI”。标题栏使用 Apple SF Symbols 关闭图标。通用页按界面、侧栏和外部工具分组，侧栏选项分为两列；可选择跟随系统、浅色或深色外观，以及界面语言。外观、语言、快捷键以及自动检查和自动下载开关即时生效；检查频率自动保存，下次启动应用后生效。Git 页的默认提交姓名与邮箱需要点击“保存”，会写入全局 Git 配置并影响其他 Git 工具。

“外部工具 → 终端”默认使用系统终端，打开设置时会在后台检测已安装的常用终端，在下拉菜单中显示并去重；macOS 使用系统应用名称，Windows 与 Linux 检测 PATH 中的常用终端。也可通过“选择其他应用…”选择终端应用；选择后自动保存，取消选择保留原值，保存失败恢复原设置。macOS 选择 `.app`，Windows 选择 `.exe`，Linux 选择可执行的终端程序。仓库列表右侧“…”菜单中的“在终端中打开”会在对应仓库目录启动所选终端；应用不存在或启动失败会显示错误。Linux 默认优先使用 `xdg-terminal-exec`，其次使用 `x-terminal-emulator`；其他自选终端需支持 `-e` 命令参数，另适配常见终端的工作目录参数。终端会话独立于 51Code，关闭应用不会结束已打开的终端。

添加仓库和扫描文件夹共用上次选择的目录，下次打开文件选择器时自动定位到该目录，重启后保留。取消选择或选择器报错不会更新记录；目录已失效或不再是目录时回退到用户目录。目录记忆不提供额外设置开关。

“启动时”默认进入仓库列表，也可选择恢复上次打开的仓库。仓库已移出列表或目录失效时回退到列表；已有窗口布局与提交草稿保留。

“仓库行为 → 文件变化时自动刷新”默认开启，仅监听当前仓库的文件及 Git 元数据，支持链接工作树。连续变化会合并刷新，前台读取、写操作、弹窗或未保存的冲突编辑期间延后处理；刷新后仓库没有变化时逐步放慢（最长约 8 秒），有变化、切回窗口或执行操作后恢复。监听采用目录变化提示，跳过 `.git` 的对象和日志目录，以及工作区中的 `node_modules`、`.mygo`、`.trail` 目录；监听中断会自动重试几次，达到系统监听上限或重试仍失败时提示错误，仍可手动刷新或切回窗口刷新。返回仓库列表、切换仓库、关闭窗口或关闭开关会停止对应监听。

“定时获取远端更新”默认关闭，开启后可选每 5／15／30 分钟，默认 15 分钟。只处理当前仓库，首次获取等待一个完整间隔；忙碌、读取中、弹窗或冲突编辑时延后，无远端或正在合并／变基时跳过。只执行 fetch，不自动拉取、合并或推送；前台操作会取消后台获取并等待清理结束；切回窗口不会打断获取，获取结束后再刷新仓库状态。网络错误显示在状态栏，不影响本地操作。返回仓库列表或关闭窗口后停止。

界面语言可选自动检测、简体中文、繁體中文或 English，选择后由 MyGo 保存，下次启动继续使用；自动检测跟随系统首选语言，未匹配到支持语言时使用简体中文。界面语言与 AI 提交说明的输出语言独立。

打开仓库后，通过工具栏或“仓库”菜单进入“仓库设置”，查看提交身份和管理远程地址。提交身份默认沿用 Git 的配置解析结果，也可勾选“为此仓库单独设置”，填写并保存仓库专属身份。取消勾选并保存会移除仓库配置中的直接身份覆盖，继续继承已有配置，不会复制全局值或修改 include、条件 include 与工作树配置。linked worktree 共用仓库级配置，工作树专属配置仍优先；“当前生效”展示实际配置值及其来源。

设置面板通过标题栏右侧的关闭按钮、`Esc` 或点击面板外关闭。身份编辑在点击“保存”前不会修改 Git 配置；点击“取消”放弃输入，其他关闭方式会在存在未保存的身份修改时要求确认。外部修改导致配置过期时会阻止覆盖，需要重新打开设置。远程以紧凑列表显示名称和地址，行末菜单提供编辑、复制地址和移除；不同的推送地址单独显示，长地址可悬停查看。远程编辑或移除完成后返回原来的设置页面。

右下角显示版本号，点击检查更新（不能自更新的安装打开下载页），悬停查看当前版本与构建信息。发现可用更新时显示“新版本 v…”，点击打开原生更新窗口；选择稍后提醒仍保留提示，跳过该版本后清除提示。通过 `51Code → 关于 51Code` 查看完整版本信息。

版本号左侧的对话气泡用于反馈，悬停提示“反馈问题或建议”，点击通过默认浏览器打开项目的 GitHub 新建 Issue 页面。

## 应用更新

在原生 `51Code` 菜单中选择“检查更新…”，或在设置中点击“立即检查更新”。开启自动检查时，正式构建在启动约 10 秒后检查，此后按设置的频率检查。支持每小时、每 6 小时、每天和每周，默认为每天；修改后下次启动应用生效。关闭自动检查时频率选择禁用，仍可手动检查更新。默认只检查并提示，由用户选择安装、稍后提醒或跳过版本。用户可在设置或更新窗口选择以后自动下载，下载完成后仍由用户决定何时重启。下载失败、取消或签名不匹配不会安装更新。

更新通过 HTTPS 从自有对象存储下载，并由 MyGo 验签安装，更新窗口同样使用原生界面。不需要 GitHub CLI、GitHub 登录或存储凭证。开发模式不执行更新。应用须安装在有写权限的位置才能自更新：macOS 从 DMG 拖入 `/Applications` 或 `~/Applications`；Windows 使用安装器（按用户安装）；Linux 使用 install.sh（安装到 `~/.local`）。deb/rpm 装在 `/opt`，不能自更新，菜单、设置页和右下角版本号改为打开 GitHub Releases 手动下载新包。普通窗口关闭、退出和更新重启都会检查正在执行的操作，保存提交说明，并询问是否丢弃未保存的冲突编辑；取消后可以继续工作。界面偏好与提交草稿保存在应用数据目录的 `native-state.json`。

安装过更新功能引入前版本的用户，需要手动安装一次包含更新功能的版本。尚未上传首个版本时，应用检查更新会报清单不存在。更新包的 Ed25519 签名不能替代 macOS 的代码签名与公证。
